# Issue の型

## 文書構成

次の順で出す。並べ替えと追加をしない。省けるのは `# バージョン` と `## SHOULD` だけ。空の見出しを残さない。

```markdown
# 概要

# 背景

# バージョン

# 受け入れ条件

## MUST

## SHOULD
```

タイトルは、概要を一文にしたものにする。本文には書かない。

### 概要

何が必要でなぜかを要約する。`# 背景` の繰り返しにしない。完了条件は `# 受け入れ条件` に回す。やり方は書かない。

### 背景

文脈と動機を書く。対象外・期待・実際・エラーもここに書く。見出しは増やさない。

バグなら期待と実際を書く。エラーがあれば添える。`## MUST` が無いときは、期待と実際が完了条件になる。

完了条件の転記にしない。やり方は書かない。

### バージョン

次のいずれか 1 つ。複数の値を並べない。完了条件は書かない。

- バグ: ユーザーが示したバージョン
- 機能追加: デフォルトブランチの short SHA
- どちらでもない: 見出しごと省く

### 受け入れ条件

`## MUST` と、あるときだけ `## SHOULD`。この見出しの直下に本文を置かない。

#### MUST

完了の最低条件。検証でき、何を満たすかを書く。やり方は書かない。1 項目は 1 つの完了条件。チェックリストにする。

````markdown
- [ ] [完了の最低条件]
````

- コードの差し方、ライブラリ名、手順は書かない
- 期待と実際の言い換えだけにしない。バグで MUST が無いなら `# 背景` の期待と実際を完了条件にする

#### SHOULD

後回しにできる条件。無ければ見出しごと省く。MUST の言い換えにしない。

````markdown
- [ ] [後回しにできる条件]
````
