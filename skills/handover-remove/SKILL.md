# handover-remove

## できること

- 現在のプロジェクトの引き継ぎノートを一覧にする
- ユーザーが選んだノートを、確認後に削除する

## いつ使うか

- `/handover-remove`
- `引き継ぎノートを削除`
- `handoverを消して`
- `古い引き継ぎを掃除して`

## 手順

### Step 1: projectを決める

`handover-create`と同じ規則で決める。リポジトリ名を、ワークツリーでも同じ名前になるよう共通の`.git`ディレクトリの親から取る。

```bash
basename "$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")"
```

Git管理外のディレクトリ、またはプロジェクト規約でGitコマンドが禁止されている場合は、カレントディレクトリ名を使う。

### Step 2: ノートを列挙する

`~/.docs/handovers/<project>/`配下の`*.md`を列挙する。

- ディレクトリがない、または0件なら、削除対象がない旨を伝えて終わる

### Step 3: 削除対象を選んでもらう

一覧を番号付きで示し、削除するノートを選んでもらう。

```text
`~/.docs/handovers/<project>/` の引き継ぎノート:
1. <filename1>
2. <filename2>
3. <filename3>
削除するものを番号かファイル名で指定してください（複数可、`all`で全件）。
```

- 依頼文に対象（「古いもの」「全部」など）が含まれていても、該当するファイルを一覧で示して選んでもらう
- 1件しかない場合も選んでもらう

### Step 4: 削除前に確認する

選ばれたファイルのパスを並べ、削除してよいか確認する。承認されたら削除する。

```bash
rm <path1> <path2>
```

### Step 5: 結果を返す

削除したファイルと、残っているノートの件数を返す。ノートが0件になった場合は、空になった`~/.docs/handovers/<project>/`も削除する。

## 禁止事項

- ユーザーが選んでいないノートを削除しない
- 確認を取らずに削除しない
- `~/.docs/handovers/<project>/`以外のファイルを削除しない
