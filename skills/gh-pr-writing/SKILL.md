# gh-pr-writing

## できること

- `references/schema.md` の型に沿って、PRのタイトルと本文を書く
- 呼び出し元が取ったPRのコミットとdiffだけを、変更内容の根拠にする
- 既存PRを更新するときは、変える箇所だけを書き直す
- 書いたタイトルと本文を`report-patterns`で見直す

## いつ使うか

- 他のスキルが`gh-pr-writing`を読むよう指示したとき
- ユーザーが`gh-pr-writing`と明示したとき

## 手順

### Step 1: 型を読む

`references/schema.md` を読む。

### Step 2: 材料を集める

変更目的、変更概要、変更詳細、テスト内容が書けるところまで、会話、Issue、呼び出し元が取ったPRのコミットとdiffから集める。

- 変更目的は、会話、Issue、コミットメッセージから取る。diffから推測しない
- 変更概要と変更詳細は、PRのdiffにある事実だけを書く
- テスト内容は、このセッションで実行・操作した結果だけを書く
- ローカルファイルや会話中の未push変更は、PRのdiffに無ければ使わない

既存PRを更新するときは、変える箇所と、それに連動して直す箇所だけを集める。

diffが無ければ本文を書かない。

### Step 3: 足りない情報を聞く

本文に書けない情報だけを、一度に一つ聞く。選択肢と推奨回答を出す。既存PRを更新するときは、変えない箇所については聞かない。

- 変更目的を書くのに必要な情報が無ければ聞く
- closeするIssueは、呼び出し元が決めたIssue、または会話で示されたIssue番号を使う

### Step 4: 書く

`references/schema.md` の型に沿って、タイトルと本文を書く。書き方は`report-patterns`にも従う。

既存PRを更新するときは、要求された変更と整合に必要な変更だけを加える。既存本文が型の見出し構成に沿っている箇所は残し、書くことが無くなった見出しは型に従って扱う。

### Step 5: 見直す

`report-patterns`を読み、Step 4のタイトルと本文がその書き方で読みやすくできるか確かめる。できる箇所があれば、見出し構成と記載した事実は変えずに直す。

## 安全条件

- `references/schema.md` と`report-patterns`を読まずに書かない
- PRのdiffにない変更を本文へ含めない
- 会話、Issue、コミット、diffで確かめていない事実を推測で書かない

## スキル連携

| ユーザーの依頼 | ワークフロー |
| --- | --- |
| PR作成 | `gh-pr-create` |
| PR更新 | `gh-pr-update` |
| Gitコマンド禁止環境でPR作成 | `gh-pr-create-no-git` |
| Gitコマンド禁止環境でPR更新 | `gh-pr-update-no-git` |
| 本文の書き方・可読性 | `report-patterns` |
