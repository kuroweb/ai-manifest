# GitHub Pull Requestの型

## タイトル

変更目的を一文で書く。

## 文書構成

見出しは次の順で出す。`### 処理フロー` 以外の見出しは省かず、書くことが無ければ `- なし` と書く。

```markdown
## 変更目的

[変更目的]

## 変更内容

### 処理フロー

[処理フロー]

### [トピック見出し]

[トピック]

## テスト内容

[テスト内容]

## レビュー観点

[レビュー観点]

## 関連リンク

[関連リンク]

[フッター]
```

### 変更目的

課題と、それをどう解決するかを段落で書く。テーマが複数あれば、テーマごとに段落を分ける。

### 変更内容

差分で何をなぜ変えたかを、処理フローとトピック見出しで書く。

#### 処理フロー

変更がまたがるコンポーネント間のやり取りを、mermaid の図で 1 つ示す。

````markdown
```mermaid
sequenceDiagram
```

- [補足]
````

- やり取りが主ならシーケンス図、分岐や状態遷移が主ならフローチャートにする
- コンポーネントは、変更の判断を担うファイル（リポジトリルートからのパス）、外部サービス、永続ストアにする
- 主要な経路だけを描き、例外やエラー処理は補足に書く
- 省略条件: 差分が 1 ファイルで閉じるとき、またはドキュメント、設定、rename、テストだけの変更のとき

#### トピック見出し

差分をテーマごとに、何をなぜ変えたかと、その振る舞いを決める関連コードを書く。1 つ以上置く。

```markdown
### [トピック見出し]

[そのトピックで何をなぜ変えたか]

- [path/to/file.ext:開始行-終了行](リンク先)
```

- トピック見出しは、名詞だけのラベルにせず、何がどう変わったかが伝わる言い方にする
- 同じ変更が複数のモジュールに並ぶときは 1 つの見出しにまとめ、関連コードは代表の 1 つにする
- 関連コードは、変更を含む関数や型、またはブロックの範囲を、head の最新コミットの blob リンクで示す

### テスト内容

レビュアーとマージを判断する人が、この PR の head で何を確かめ、結果がどうだったかを読み取れるように、表で書く。

```markdown
| 観点 | 分類1 | 手順 | 期待値 | 結果 |
| --- | --- | --- | --- | --- |
| [観点] | [分類1] | [手順] | [期待値] | [結果] |
```

観点は次の表から選ぶ。行は観点の順に並べる。

| 観点 | 何を確かめるか |
| --- | --- |
| 正常系 | 変更した振る舞いが想定した入力で期待どおり動くか |
| 異常系 | 不正な入力やエラーのとき期待どおり振る舞うか |
| 境界値 | 上限・下限・0件・空など境目で期待どおりか |
| 回帰検証 | 既存の振る舞いが変わっていないか |
| 静的検査 | lint・型検査・`git diff --check` など |
| 差分検証 | 実際に動かして期待どおりか |

- 分類は `分類1` から始め、必要に応じて `分類2`、`分類3` と増やす
- 分類1 には、観点の中で行をまとめる単位（対象の機能やコンポーネント）を書く
- 手順は、自動テストならテスト範囲を指す head の最新コミットの blob リンクと、実行したコマンドを書く。全体を実行したときはコマンドだけ書く。手動なら行った操作を書く
- 期待値は、あるべき振る舞いを書く
- 結果は ✅、❌、未実施 のいずれかにする。❌ のときだけ、実際に起きたことを短く添える。未実施のときは、理由を添える
- ✅ か ❌ にするのは、head の最新コミットで確かめたものだけにする。それより前のコミットでしか確かめていないものは未実施にし、理由にそのことを書く

### レビュー観点

レビュアーが、差分のどこを重点的に見ればよいかが分かるように、表で書く。確信が持てない箇所や、ほかの選択肢がある中で選んだ判断など、レビュアーの目が要るものに絞る。

```markdown
| 重要度 | 確認してほしいこと | 対象 |
| --- | --- | --- |
| [重要度] | [確認してほしいこと] | [対象] |
```

- 重要度は、表の中で改行されないよう `&nbsp;` でつないだ `🔴&nbsp;CRIT`、`🟠&nbsp;HIGH`、`🟡&nbsp;MED`、`🟢&nbsp;LOW` から選ぶ
- 行は重要度の高い順に並べる
- 確認してほしいことは、「[状況や判断]が、[確かめてほしいこと]か」のように背景を含めた `〜か` の問い
- 対象は、変更後の行を指す head の最新コミットの blob リンク。コードの外なら、その名前

### 関連リンク

```markdown
## 関連リンク

- [リンクの種類]: [URL]
```

- 中身はリンクの箇条書きにし、書くリンクが無ければ `- なし` と書く。URL の無いものは書かない

### フッター

```markdown
Closes #[番号]
```

- 見出しを付けず、本文の最後（関連リンクの後）に置く
- この PR で完了する Issue を `Closes #[番号]` で書く
- close する Issue が無ければ、フッターごと省く
