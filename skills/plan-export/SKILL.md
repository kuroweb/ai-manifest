# plan-export

## できること

- 会話で合意したプランを、再利用できる形で保存する
- 保存したファイルのパスを返す

## いつ使うか

- `plan-export`
- プランを保存して
- 相談したプランを ~/.docs/plans に出力して
- この計画を書き出して
- 次のセッションへの引き継ぎを書くときは使わない。`handover-create`を使う

## 手順

### Step 1: プラン内容を抽出する

現在の会話から、合意済みのプラン内容だけを抽出する。未確定事項と決定事項を分ける。

### Step 2: 整形するかを決める

次のどれかに当てはまれば、原文をそのまま使う。

- `plan` モードや planner エージェントの出力が、すでに見出し付き Markdown になっている
- ユーザーが「この内容をそのまま保存して」と明示している
- 追記なしで次回参照できるだけの情報量がある

次のどれかに当てはまるときだけ、`references/schema.md` を読み、その型で最小限に整形する。

- 会話断片しかなく、保存しても再利用しにくい
- 箇条書きの順序や区切りを付けるだけで可読性が大きく上がる
- 未確定事項を別立てにしないと誤読しやすい

整形するときは、実装詳細よりも意思決定と段取りが再開できることを優先する。冗長な議事録にせず、次回すぐ着手できる粒度にする。

### Step 3: 保存先を決める

```bash
mkdir -p ~/.docs/plans
date +%Y-%m-%d_%H%M
```

ファイル名は `YYYY-MM-DD_HHmm_<slug>.md` にする。`<slug>` はプランの主題を 3 語前後で短く表した ASCII のケバブケースにする。主題が決めにくい場合は `plan` を使う。同名のファイルがある場合は末尾に `_2` などの連番を付ける。

### Step 4: 保存してパスを返す

Step 2 の本文を Step 3 のパスに保存し、`~`を展開した絶対パスで返す。

`~/.docs/plans` への書き込みがサンドボックス外になる環境では、権限昇格が必要な旨を明示し、承認を得てから保存する。保存できなかったときは、保存予定だった本文をそのまま返す。

## 禁止事項

- 会話に出ていない内容を補わないこと
- 原文のニュアンスや優先順位を変えないこと
- 曖昧な点を推測で埋めないこと

## スキル連携

| ユーザーの依頼 | ワークフロー |
| --- | --- |
| 相談したプランを保存 | `plan-export` |
| 次のセッション用の引き継ぎノートを作成 | `handover-create` |

## コマンドリファレンス

| コマンド | 用途 |
| --- | --- |
| `mkdir -p ~/.docs/plans` | 保存先を作成する |
| `date +%Y-%m-%d_%H%M` | ファイル名の日時を取得する |
