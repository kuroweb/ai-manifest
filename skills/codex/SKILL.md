# Codex

Codex CLIをサブエージェントとして実行し、レビュー・分析・相談を行うスキル。ファイル変更を伴う作業は `codex-implement` スキルを使う。

## 実行コマンド

```bash
codex exec --full-auto --model gpt-5.4 --sandbox read-only --cd <project_directory> "<request>"
```

- `--sandbox read-only` で読み取り専用。ファイルは変更されないため安全に相談・分析に使える
- 調査・レビューは長時間かかることがあるため、実行時のタイムアウトは10分程度に設定する

## プロンプトの組み立て

codexはこちらの会話コンテキストを一切持たない。`<request>` に以下を含める：

1. **依頼内容と背景**: 対象ファイルパス・関数名・エラーメッセージなど、こちらで判明している情報はすべて渡す（codexに再調査させない）
2. **観点**: レビュー・評価系では見てほしい観点を明示する（下記テンプレート参照）
3. **固定指示（末尾に必ず追加）**:

   > 確認や質問は不要です。具体的な提案・修正案・コード例まで自主的に出力してください。

### 観点テンプレート（UI/UXレビュー）

- UIデザイン評価: 「あなたは世界トップクラスのUIデザイナーです。(1) 視覚的階層構造とタイポグラフィ、(2) 余白・スペーシングのリズム、(3) カラーパレットのコントラストとアクセシビリティ、(4) インタラクションパターンの一貫性、(5) ユーザーの認知負荷の軽減、の観点で評価してください。」
- ユーザビリティ分析: 「UXリサーチャー兼デザイナーとして、Nielsen の10ヒューリスティクスに基づき、(1) エラー防止の仕組み、(2) ユーザーの制御と自由度、(3) 一貫性と標準、(4) 認識vs記憶の負荷、(5) 柔軟性と効率性、を評価してください。」

## 実行手順

1. 上記コマンドでcodexを実行する
2. codexの出力を鵜呑みにせず、指摘・提案が対象コードの実態と合っているか要点を確認する
3. 結果をユーザーに報告する
