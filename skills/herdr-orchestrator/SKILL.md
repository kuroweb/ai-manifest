# herdr-orchestrator

## できること

- ワーカーを起動する場所を決める
- ワーカーのエージェントとモデルを選ぶ目安を示す
- ワーカーへの依頼と完了の待ち方、ワーカーが止まったときの扱いを決める
- 使い終わったワーカーを整理する

## いつ使うか

- ユーザーが`herdr-orchestrator`と明示したとき

## ワーカーの配置

- ワーカーは、1人につき1つのタブに起動する。タブ名はワーカー名にする
- ワーカーの作業場所は、作業内容に合わせて決め、`--cwd`で渡す。リポジトリでの作業なら、対象リポジトリのルートにする。省くと、スクリプトを実行したディレクトリになる
- ワーカーは`scripts/spawn-worker.sh`で起動する。タブの作成と`herdr agent start`はスクリプトに任せ、自分で行わない

```bash
bash scripts/spawn-worker.sh [--cwd <ディレクトリ>] <ワーカー名> <エージェントの種類> [エージェントの引数...]
```

| 出力の項目 | 内容 |
| --- | --- |
| `name` | ワーカー名。`herdr agent`の対象に使う |
| `cwd` | ワーカーの作業場所 |
| `tab_id` | ワーカー用タブのID |
| `pane_id` | ワーカーのペインID |
| `status` | `ready`は依頼を送れる状態。`blocked`は起動時のダイアログで止まっている |

## エージェントとモデルの選び方

ワーカーごとに、作業に合うエージェントとモデルを選ぶ。ユーザーが指定したときはそれに従う。目安は次のとおり。

| 作業 | 目安 |
| --- | --- |
| 設計判断を含む実装、原因の分からない不具合の調査 | 高性能なモデル |
| 方針が決まった実装、範囲の決まった調査 | 標準的なモデル |
| 機械的な置換、定型的な確認 | 軽量なモデル |
| 他のワーカーの成果物のレビュー | 作ったワーカーと別の種類のエージェント |

モデルは、スクリプトの`[エージェントの引数...]`に各エージェントのモデル指定（例: `--model`）を渡して選ぶ。

## 作業の依頼と待機

- 作業の依頼は、`spawn-worker.sh`が返したワーカー名へ`herdr agent prompt`で送る
- 依頼は`--wait --until working`を付けて送り、作業が始まったところで次へ進む。複数のワーカーには全員へ送ってから待つ
- 完了は`scripts/wait-worker.sh`で待つ。`herdr agent wait`は、作業の途中で一瞬`done`になるエージェントで早く返るため使わない
- `herdr agent send-keys`で応答した後は、`herdr agent wait --until working`で作業の再開を確かめてから完了を待つ
- 完了を待った後は、`herdr agent read`で画面を読み、承認や質問で止まっていないか確かめる。エージェントによっては、承認待ちでも`idle`と判定される
- ワーカーが承認や質問で止まっていたら、どのワーカーが何を聞いているかをユーザーに伝える。ユーザーの答えを受けてから`herdr agent send-keys`で応答し、自分では答えない
- `spawn-worker.sh`が`status: blocked`を返したときも、同じように画面を読んでユーザーに伝える

```bash
bash scripts/wait-worker.sh <ワーカー名> [タイムアウト秒]
```

| 出力の`status` | 内容 |
| --- | --- |
| `idle`・`done` | 作業を終えて入力待ち |
| `blocked` | 承認や質問で止まっている |
| `unknown` | 状態を判定できない |
| `timeout` | タイムアウトまで作業が続いた |

## ワーカーの整理

- 結果を回収し、続けて依頼しないワーカーは、そのタブを閉じる。続けて依頼するワーカーは残す
- タブは`herdr tab close <tab_id>`で閉じる。`tab_id`は`spawn-worker.sh`の出力か`herdr agent get <ワーカー名>`で取る
