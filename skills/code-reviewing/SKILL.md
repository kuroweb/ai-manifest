# code-reviewing

## できること

- 渡されたdiffと変更目的を一次情報としてレビューする
- `references/code-review-schema.md` の文書構成でレビュー結果を組み立てる
- レビュー結果をチャットへ返す

## いつ使うか

- 他のスキルが`code-reviewing`を読むよう指示したとき
- diffと変更目的が、呼び出し元または会話から渡されたとき

## 手順

### Step 1: diffを確認する

diffは必須である。呼び出し元または会話に無いときは、レビュー結果を生成しない。

### Step 2: 変更目的を決める

変更目的は次の順で決める。

1. 呼び出し元が渡した変更目的
2. 会話で示された変更目的
3. ユーザーに聞く

無ければ、一度に一つ聞く。PR本文の貼り付けでもよい。diffから変更目的を推測しない。

変更目的とdiffが矛盾した場合は、自動解決せず確認する。

### Step 3: 差分を評価する

- diffと変更目的を照合し、意図しない変更や不足を確認する
- APIキー、トークン、パスワード、秘密鍵、接続文字列、個人情報など、機密情報がdiffに含まれていないか確認する
- 認証・認可、入力値の扱い、インジェクションなど、差分に関連するセキュリティリスクを確認する
- 必要に応じて`AGENTS.md`、周辺コード、既存テストを読む
- 対象リポジトリのローカル規約を優先する

### Step 4: レビュー結果を組む

本文を組む前に `references/code-review-schema.md` を読む。本文はその文書構成に従う。

- 判定と指摘は、diffと変更目的にある事実から書く
- diffにない事実を断定しない

### Step 5: レビュー結果を返す

Step 4の本文をチャットへ返す。

## 安全条件

- diffなしでレビュー結果を生成しない
- `references/code-review-schema.md` を読まずに本文を組まない
- diffにない事実を断定しない
- 変更目的をdiffから推測しない

## スキル連携

| 状況 | 使用するスキル |
| --- | --- |
| 渡されたdiffをレビューする | `code-reviewing` |
| ローカルブランチのdiffをgitで取る | `code-review` |
| AIによるGitコマンド実行が禁止されている | `code-review-no-git` |
| 指定したGitHub PRをレビューする | `gh-pr-review` |
| 指定したGitLab MRをレビューする | `glab-mr-review` |
