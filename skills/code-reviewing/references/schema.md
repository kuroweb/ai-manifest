# コードレビューの型

## 文書構成

次の順で出す。`##` と `###` の見出しは省略・並べ替え・追加をしない。空なら `なし`。

````markdown
## レビュー結果

**リスクレベル**: [全体のリスクレベル]

## 総評

[全体のリスクレベルの理由]

## 指摘事項

### Critical

#### [レビューカテゴリ] [問題を言い切る一文]

- 対象ファイル:
  - [対象ファイル]
- 問題:
  - [何が問題か]
- 影響:
  - [何が起きるか]
- 修正案:
  - [どう直すべきか]

    ```[言語]
    [修正後のコード]
    ```

- 補足:
  - [補足すること]

### High

### Medium

### Low
````

### レビュー結果

全体のリスクレベルだけを書く。その理由は `## 総評` に回す。

```markdown
**リスクレベル**: [全体のリスクレベル]
```

- `[全体のリスクレベル]` は、報告した問題のうち最も高いリスクレベル。問題が無ければ `🟢LOW`

  | 最も高いリスクレベル | `[全体のリスクレベル]` |
  | --- | --- |
  | `Critical` | `🔴CRITICAL` |
  | `High` | `🟠HIGH` |
  | `Medium` | `🟡MEDIUM` |
  | `Low`、または問題なし | `🟢LOW` |

- 絵文字とリスクレベルは表の組み合わせで固定する

### 総評

全体のリスクレベルの理由と、確認が必要な事項を書く。後段の指摘を転記しない。

```markdown
[全体のリスクレベルの理由]
```

- `[全体のリスクレベルの理由]` は、変更目的との整合と、全体のリスクレベルを決めた根拠
- 確認が必要な事項があれば、理由の後に書く。例: diff が途中で切れている、変更目的が分からない

### 指摘事項

再確認を通った問題を、リスクレベルごとに書く。

```markdown
### [リスクレベル]

#### [指摘見出し]

[対象ファイル]
[問題]
[影響]
[修正案]
[補足]
```

#### リスクレベル

- `Critical`、`High`、`Medium`、`Low` の4つを必ず置く。指摘が無ければ下に `なし`
- 1つのリスクレベルに複数あれば、影響の大きい順に並べる

#### 指摘見出し

```markdown
[レビューカテゴリ] [問題を言い切る一文]
```

- `[レビューカテゴリ]` は、SKILL.md の Step 6 で付けたレビューカテゴリを角括弧ごと書く。例: `[セキュリティ]`
- `[問題を言い切る一文]` は「〜について」のような題目にしない
- SKILL.md の Step 5 で信頼度が中になった問題は、末尾に `（要確認）` を付ける

#### 対象ファイル

```markdown
- 対象ファイル:
  - [[path]:[開始]-[終了]]([blobリンク])
```

- 箇所が複数あれば行を分けて並べる
- `[開始]-[終了]` は変更後の行番号。1行だけなら `[開始]` のみ
- 指す行が無いときは `:[開始]-[終了]` と `[blobリンク]` の `#L` 以降を省き、ファイル単位で書く
- `[blobリンク]` は次の形。`[sha]` は呼び出し元が渡したフルSHA。ブランチ名だと後のpushで指す行がずれる

  | サービス | `[blobリンク]` |
  | --- | --- |
  | GitHub | `https://[host]/[owner]/[repo]/blob/[sha]/[path]#L[開始]-L[終了]` |
  | GitLab | `https://[host]/[project]/-/blob/[sha]/[path]#L[開始]-[終了]` |

- リンクの基点が渡されないとき、または削除された行を指すときは、リンクにせず `[path]:[開始]-[終了]` だけ書く

#### 問題

```markdown
- 問題:
  - [何が問題か]
```

- `[何が問題か]` は、コードが何をしているかを事実で書く。複数あれば行を分けて並べる

#### 影響

```markdown
- 影響:
  - [何が起きるか]
```

- `[何が起きるか]` は、どの入力や状態で何が起きるか。複数あれば行を分けて並べる

#### 修正案

````markdown
- 修正案:
  - [どう直すべきか]

    ```[言語]
    [修正後のコード]
    ```
````

- `[どう直すべきか]` は、直し方を書く。複数あれば行を分けて並べる
- `[修正後のコード]` は任意。付けるときは該当する `[どう直すべきか]` の下に入れ子で置く

#### 補足

```markdown
- 補足:
  - [補足すること]
```

- `[補足すること]` は、追加で調べるべきことや前提など、指摘を補う情報。複数あれば行を分けて並べる
- 不要なら、`[補足]` ごと省く
