# コードレビューのチェックリスト

## 確認の優先順

1. セキュリティ: 脆弱性、シークレット、インジェクション
2. 正確性: ロジックの誤り、破壊的変更
3. 性能: 非効率、リソースリーク
4. 品質: 保守性、読みやすさ
5. スタイル: フォーマット、命名（自動化に任せる）

## セキュリティ

### シークレットと認証情報

- [ ] APIキー、パスワード、トークンがハードコードされていない
- [ ] ログやエラーメッセージに認証情報が含まれていない
- [ ] シークレットを環境変数やシークレット管理から読み込んでいる

### インジェクション

- [ ] SQLはパラメータ化したクエリを使っている
- [ ] ユーザー入力をHTMLに出力する前にエスケープしている（XSS）
- [ ] シェルコマンドにユーザー入力を含めていない（コマンドインジェクション）
- [ ] ファイルパスを検証している（パストラバーサル）

### 認証・認可

- [ ] 保護すべきエンドポイントすべてで認証・認可を確認している
- [ ] セッションを適切に扱っている
- [ ] パスワードを平文ではなくハッシュで扱っている

### 設定

- [ ] 安全でない設定が無い

### データの露出

- [ ] 機密データをログに出していない
- [ ] APIレスポンスに内部の詳細が漏れていない
- [ ] エラーメッセージにシステム情報が露出していない

## 正確性

### ロジック

- [ ] null、空、境界値などのエッジケースを扱っている
- [ ] エラーになる条件を適切に扱っている
- [ ] 非同期処理を正しく待っている
- [ ] 競合状態を考慮している

### 破壊的変更

- [ ] APIの契約を保っている
- [ ] DBマイグレーションを戻せる
- [ ] リスクの高い変更にフィーチャーフラグを使っている

### テスト

- [ ] 新しいコードにテストがある
- [ ] 正常系だけでなく、エラーの経路もテストしている
- [ ] 既存のテストが通る

## 性能

### 効率

- [ ] N+1クエリが無い
- [ ] クエリに必要なインデックスがある
- [ ] 適切なデータ構造を使っている
- [ ] 不要なループや繰り返しが無い
- [ ] 重い処理にキャッシュを検討している

### リソース

- [ ] DB接続を閉じるか、プールしている
- [ ] ファイルハンドルを閉じている
- [ ] メモリリークが無い（イベントリスナーの解除など）

### 規模

- [ ] 現実的なデータ量で動く
- [ ] 大きな結果セットをページネーションしている
- [ ] 外部呼び出しにタイムアウトがある

## 品質

### 読みやすさ

- [ ] 名前が明確で、中身を表している
- [ ] 関数が1つのことだけをしている
- [ ] 条件式が複雑すぎない
- [ ] コメントが「何を」ではなく「なぜ」を説明している

### 保守性

- [ ] コードの臭い（長いメソッド、大きなクラス、密結合）が無い
- [ ] SOLID原則に反していない
- [ ] コピー&ペーストによる重複が無い
- [ ] 抽象化が適切である
- [ ] 依存の追加に理由がある
- [ ] 使われないコードが無い

### 一貫性

- [ ] プロジェクトのパターンに沿っている
- [ ] 既存のコードスタイルに合っている
- [ ] 既存のユーティリティやヘルパーを使っている
- [ ] API設計が既存と一貫している

## 最低限の確認

急ぐときも、少なくとも次は確認する。

1. シークレットや認証情報が含まれていないか
2. SQLやコマンドのインジェクションが無いか
3. エラーになる場合を扱っているか
4. 新しいコードにテストがあるか
