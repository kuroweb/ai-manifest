# コードレビューのチェックリスト

## 確認の優先順

1. セキュリティ: 脆弱性、シークレット、インジェクション
2. 正確性: ロジックの誤り、破壊的変更
3. 性能: 非効率、リソースリーク
4. 品質: 保守性、読みやすさ
5. スタイル: フォーマット、命名（自動化に任せる）

## セキュリティ

### シークレットと認証情報

- [ ] APIキー、パスワード、トークンがハードコードされていない
- [ ] ログやエラーメッセージに認証情報が含まれていない
- [ ] シークレットを環境変数やシークレット管理から読み込んでいる

### 入力の検証

- [ ] 外部APIの応答、アップロード、メッセージを含む未信頼の入力の型・長さ・範囲を、危険な処理に渡す前に検証している
- [ ] 認可、入力検証、エスケープ、署名検証などの既存の防御を削除したり迂回したりしていない

### インジェクション

- [ ] SQLはパラメータ化したクエリを使っている
- [ ] ユーザー入力がNoSQLやLDAPのクエリ構文として解釈されない
- [ ] ユーザー入力をHTMLに出力する前にエスケープしている（XSS）
- [ ] シェルコマンドにユーザー入力を含めていない（コマンドインジェクション）
- [ ] 未信頼の入力をコードやテンプレートとして評価していない
- [ ] ファイルパスを検証している（パストラバーサル）
- [ ] 未信頼の入力を安全でないデシリアライズ処理に渡していない
- [ ] 未信頼のキーを使った代入やマージで、プロトタイプが汚染される経路が無い

### 外部通信

- [ ] 未信頼の入力で接続先を指定するとき、リダイレクト先も含めて許可していない宛先へ接続する経路が無い（SSRF）
- [ ] TLS証明書の検証を無効にしていない

### 認証・認可

- [ ] 保護すべきエンドポイントすべてで認証・認可を確認している
- [ ] 対象オブジェクトとテナントごとに、利用者がその操作を行えるかをサーバー側で確認している（IDOR）
- [ ] 業務上の制約をサーバー側で確認し、再送や順序の入れ替えで迂回できない
- [ ] トークンや署名付き入力の署名、有効期限、利用先を検証している
- [ ] 認証や権限の変更時にセッションを更新し、ログアウトや失効後のセッションを受け付けない
- [ ] セッションCookieのSecure、HttpOnly、SameSiteを設定している
- [ ] パスワードを平文ではなくハッシュで扱っている

### 暗号と完全性

- [ ] 用途に適した暗号方式と、暗号論的に安全な乱数源を使っている
- [ ] 外部から取得した更新物やデータを、署名などで真正性と完全性を確かめてから使っている

### 設定と権限

- [ ] CORSで許可するオリジンと資格情報の組み合わせが、意図しない相手へデータを公開しない
- [ ] 本番でデフォルトの認証情報、デバッグ機能、不要な管理機能を有効にしていない
- [ ] 実行アカウント、トークン、CIのジョブに、必要な範囲を超える権限を与えていない
- [ ] 追加・更新する依存の取得元とバージョンの固定が、既存と同じ水準である

### データの露出

- [ ] 認証情報や個人情報などの機密データをログに出していない
- [ ] APIレスポンスに内部の詳細が漏れていない
- [ ] エラーメッセージにシステム情報が露出していない

## 正確性

### ロジック

- [ ] null、空、境界値などのエッジケースを扱っている
- [ ] エラーになる条件を適切に扱っている
- [ ] 非同期処理を正しく待っている
- [ ] 競合状態を考慮している

### 破壊的変更

- [ ] APIの契約を保っている
- [ ] DBマイグレーションを戻せる
- [ ] リスクの高い変更にフィーチャーフラグを使っている

### テスト

- [ ] 新しいコードにテストがある
- [ ] 正常系だけでなく、エラーの経路もテストしている
- [ ] 既存のテストが通る

## 性能

### 効率

- [ ] N+1クエリが無い
- [ ] クエリに必要なインデックスがある
- [ ] 適切なデータ構造を使っている
- [ ] 不要なループや繰り返しが無い
- [ ] 重い処理にキャッシュを検討している

### リソース

- [ ] DB接続を閉じるか、プールしている
- [ ] ファイルハンドルを閉じている
- [ ] メモリリークが無い（イベントリスナーの解除など）

### 規模

- [ ] 現実的なデータ量で動く
- [ ] 大きな結果セットをページネーションしている
- [ ] 外部呼び出しにタイムアウトがある

## 品質

### 読みやすさ

- [ ] 名前が明確で、中身を表している
- [ ] 関数が1つのことだけをしている
- [ ] 条件式が複雑すぎない
- [ ] コメントが「何を」ではなく「なぜ」を説明している

### 保守性

- [ ] コードの臭い（長いメソッド、大きなクラス、密結合）が無い
- [ ] SOLID原則に反していない
- [ ] コピー&ペーストによる重複が無い
- [ ] 抽象化が適切である
- [ ] 依存の追加に理由がある
- [ ] 使われないコードが無い

### 一貫性

- [ ] プロジェクトのパターンに沿っている
- [ ] 既存のコードスタイルに合っている
- [ ] 既存のユーティリティやヘルパーを使っている
- [ ] API設計が既存と一貫している

## 最低限の確認

急ぐときも、少なくとも次は確認する。

1. シークレットや認証情報が含まれていないか
2. SQLやコマンドのインジェクションが無いか
3. 対象オブジェクトごとに認可を確認しているか
4. エラーになる場合を扱っているか
5. 新しいコードにテストがあるか
