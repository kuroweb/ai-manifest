# report-question

## できること

- 個別スキルに当てはまらない問いを、コード、MCP の取得結果、ユーザーが示した資料から調べる
- 結果を日本語 Markdown として `report-question-[slug].md` に保存する

## いつ使うか

- `report-question`
- `/report-question`
- 調べてレポートして
- 調査結果をまとめて
- これについて調べて

## 実行手順

### 1. 問いを確認する

問いは必須。調査の前にヒアリングする。確認した内容はレポートの `## 調査目的` にし、`# [タイトル]` はその端的な表現にする。

「何を明らかにしたいか」を短く書いてもらう。範囲、見ないもの、貼り付け、URL でもよい。

問いが曖昧なまま調査に入らない。

slug もここで決める。並列の調査で、別の問いが同じファイルを上書きしないようにする。

- 問いに沿った kebab-case。英小文字とハイフンだけ
- ユーザーが slug を指定したら、それを使う
- 同じ slug のファイルが別の問いのときは、slug を変える

### 2. 一次情報を調べる

レポートを書く前に、問いに必要な一次情報を調べる。調べるまでレポートは生成しない。

- コードが根拠になる問いは、コードベースを読む。パスと行番号、答えに効く根拠を残す
- コード以外が根拠になる問いは、使える MCP やユーザーが示した資料を読む。取得元が分かる資料を残す
- 見つからないことは「ない」と断定せず、見つからなかったと書く
- MCP や資料が取れないときは、その一次情報が取れなかったと書く。推測で埋めない
- 必要に応じて `AGENTS.md`、周辺コード、既存テスト、設計資料を読む
- 対象リポジトリのローカル規約を優先する

問いと一次情報が矛盾した場合は、自動解決せず確認する。

### 3. 結果を組み立てる

このステップの前に `references/report-schema.md` でレポートの型を確認する。書き方は `report-patterns` に従う。

### 4. 可読性を確認する

保存する前に `report-patterns` を読み、手順 3 の本文がその書き方で読みやすくできるか確認する。できる箇所があれば、調査結果と節の順は変えずに直す。

### 5. 保存して返す

手順 4 を経た本文をワークスペースルートの `report-question-[slug].md` に書き出す。

同じ slug で同じ問いのファイルがあれば上書きする。保存後、保存先パスと本文をチャットへ 1 回だけ返す。

## 禁止事項

- `references/report-schema.md` を読まずに出力しない
- `report-patterns` を読まずに可読性を確認しない
- 一次情報を調べる前にレポートを生成しない
- 調査していない事実を断定しない
- 見つからないことを「存在しない」と言い切らない
- ヒアリングしていない問いを推測で埋めない
- MCP の接続設定、導入手順、パッチ、PoC、実装手順を書かない
